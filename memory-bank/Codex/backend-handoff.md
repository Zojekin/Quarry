# 后端 Agent 交接：前端定稿后的契约补齐

核查日期：2026-11-10。本文记录本轮核查结果，不表示已实现；本轮只更新文档，不修改后端。

## 1. 接手顺序与边界

1. 阅读AGENTS、architecture、design-document，以及 `frontend-current-spec.md`。再核对shared/server/database和现有测试，不能照原型store复制业务规则。
2. 本文区分“已核实差异”“已有能力待验证”“建议方案”。接口路径/字段名尚未定稿的部分由接手Agent提出统一契约并落入shared，禁止把建议当已有API。
3. 先完成会话恢复/结束/计时和查询语义，再补标签颜色、文件夹归档与查询投影；最后做真实客户端对接。不得重写已有领域层与备份系统来迁就演示数据。
4. 保持Web→BackendClient→标准HTTP→服务/仓储的边界。工作区标签、页面滚动、视觉令牌属于前端；产品元信息属于构建配置；不为这些另造业务表。

## 2. 已核实差异与验收要求

| 优先级/主题 | 当前代码事实 | 需要补齐及验收 |
| --- | --- | --- |
| P0 草稿/恢复 | `routes/sessions.ts`只有列表/详情/开始/提交单题/交卷/暂停/恢复；SessionState无草稿和当前题位置 | 定义保存草稿/恢复位置契约，刷新与退出恢复；草稿不产生作答记录、统计或错题。锁定题不可被草稿覆盖，考试可修改且不返回答案。位置可作为会话UI元数据，不与题目快照混用 |
| P0 练习结束 | submitQuestion在全部题有记录时自动complete；无显式结束练习路由，且允许completed状态再次submitQuestion | 与侧栏显式结束、跳题保留未答、重做新尝试对齐。未答不能计量；明确完成后是否允许重做/如何记录新尝试，避免绕过状态。不要直接把结束练习映射为考试交卷 |
| P0 计时/期限 | complete按start_time到当前减paused_duration算有效时间；daily_metrics由此生成；路由未见心跳/离开/恢复进度协议 | 验证正常退出、睡眠、异常中断不计整段离线；失焦继续、暂停停止；按实际有效区间跨午夜拆分。不能仅依赖前端定时器触发考试到期，后端需校验截止时间及暂停到期处理 |
| P0 幂等/重试 | submitQuestion校验attempt_index递增，重复请求会冲突；交卷也有状态限制 | 验证响应丢失后重试不重复计量/错题；能取回已持久化结果而非诱使客户端新建尝试。具体幂等键/结果恢复策略待设计 |
| P1 多维筛选 | MistakeService.list仅单type、tags、来源题目ID、mastery、ids；tags.every；source代表source_question_id | 支持多题型、来源套题、文件夹后代、标签、收录日期、搜索；同维OR跨维AND，区分all/none。来源套题不能用source_question_id冒充。列表与选题组卷采用同一投影 |
| P1 通用查询 | Question路由只接单type；TagService.matches使用every；bank列表未传folder_id时遍历全部 | 定义数组与缺省/空数组语义，避免全不选返回全部；明确根目录与无限定不同。直接子项、文件夹导航、计数及分页/搜索须一致。评估旧调用兼容，不能无审计全局改matches |
| P1 标签颜色 | shared TagSchema及tags创建路由无color，未见设置路由；原型按命名空间＋名称存色 | 决定颜色存标签元数据还是独立偏好，按稳定ID寻址，保证两命名空间隔离；定义修改和读取接口、迁移、默认值、备份恢复。自动保存成功后才回显最终值，连续选色不被旧响应覆盖 |
| P1 文件夹导出 | BackupService.export只接受bank/banks/paper/papers | 补文件夹子树归档，定义正式格式版本、附件/文件标签/关系、ID重建、校验及事务；内容导出不带学习记录。不是直接采用quarry-preview-folder格式 |
| P1 错题来源投影 | shared MistakeRecord有源题目/版本、study_record_ids；没有直接来源套题名称字段 | 验证能从历史记录/会话快照投影历史套题身份名称、错误次数/时间和文件夹筛选数据，删除/改名不能篡改错误历史；必要时增字段并迁移，不靠当前文件名猜来源 |
| P2 学习记录/首页 | sessions列表返回全量详情；analytics/dashboard有累计/去重/用时/热力图 | 先复用聚合；按需定义轻量记录列表、恢复进度、待复习概况和未完成摘要，避免N+1及暴露考试答案。统计不能使用原型936基线 |

## 3. 已有能力，先验证再扩展

- 文件夹/题库/套题/题目CRUD、文件与题目标签隔离、六类型判分、来源跟随与快照、错题掌握/组卷、回收站、附件、内容导入导出与全量备份已有实现。先检查现有测试和真实响应，不从零重建。
- 编辑需覆盖界面所有可编辑字段，尤其标签、解析、分值及严格填空；稳定选项ID与版本更新、paper副本和源题隔离、跟随不改分值和历史会话都要联调。
- shared实体schema不等同所有实际HTTP返回；例如StudySessionSchema描述与SessionService.get投影字段不同。需要明确请求/响应DTO与校验，统一snake_case/camelCase适配、时间单位、日期时区和错误结构。
- 非严格填空/主观题不自动判分且不计可判分总分；详情文案“总分”不能据此改变领域计算。手动加入错题仍需保留。
- 普通预览不得创建会话或计时；考试提交前和未确认的练习题，其答题会话响应不得通过详情/查询泄漏答案；管理编辑API仍按既有职责提供完整内容。不要直接复用完整QuestionView给答题端。
- 来源跟随的预览、关闭冻结、删除保留最后快照，以及完整材料/固定组/分区与选项打乱都需保留；UI简化不意味着删接口。

## 4. 待定方案：接手后应明确记录决策

### 标签颜色

建议优先评估作为标签展示元数据，跟随稳定tag_id；若选择本地偏好表，也须定义备份、标签删除和重名规则。存储归属是待定技术决策，接手Agent可在现有架构内选择并记录理由，不需要为常规实现反复请求批准。先确定格式（如规范化#RRGGBB）、默认回退、缺省迁移、读写响应及并发策略。当前只有改色，没有完整重命名/合并标签管理需求，不扩展成新标签管理器。

### 筛选及历史来源

建议公共查询schema表达all/none/部分选择，不以空数组兼任全部；新增参数应兼容旧客户端或明确版本。日期边界按配置时区换算，包含起止日。历史套题已删除、文件夹已移动时按当前归属还是历史归属筛选尚需明确；不能用随意回退得到不稳定结果。

### 会话生命周期

需要同时定义draft、提交锁定、新尝试、暂停、退出、显式结束、到期、崩溃恢复的状态表和事务。多标签可打开同一会话，避免两个客户端/标签互相覆盖；具体采用版本冲突或其他方案由实现确定。界面文案“查看答案”已经定稿，不自行换回确认答题。

## 5. 最小验收清单

- 空选/全选/多选、根目录/子目录、同维OR、跨维AND、日期边界、来源删除及过滤后组卷结果一致。
- 标签自动保存与失败恢复、命名空间隔离、旧数据库迁移、备份恢复，以及连续改色的最终值一致。
- 草稿刷新/退出恢复、提交后锁定、重试幂等、重新作答历史、显式结束、空白题、暂停/恢复、超时考试、异常恢复、跨午夜计时。
- 考试答案隐藏、已删除来源快照保留、修改源题不改已有会话/错题。
- 文件夹导出→导入回环、附件完整、ID/引用重建、非法归档整份拒绝和事务回滚。
- 通过已有后端测试与针对真实差异的新增测试；更新shared契约说明、architecture、progress，注明实际已完成/待定，不把文档勾选当测试证据。
