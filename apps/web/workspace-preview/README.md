# 题匣统一页面预览

从仓库根目录运行：

```powershell
node apps/web/workspace-preview/serve.mjs
```

打开 <http://127.0.0.1:4177/>。原首页方向比较仍在4176，两个入口相互独立。

## 页面与交互

| 页面 | 地址 | 可体验的内容 |
| --- | --- | --- |
| 学习概览 | `#/home` | 继续练习、错题入口、年度作答量/用时切换 |
| 资料库 | `#/library` | 文件夹、搜索、类型筛选、列表/卡片、新建、导入导出 |
| 题库 | `#/bank/bank-math` | 题目预览、新增题目、筛选选题、保存套题 |
| 套题详情 | `#/paper/paper-math` | 属性、组成、添加题目、预览、开始练习/考试 |
| 练习与考试 | 从套题开始 | 题目导航、确认锁定、解析、重做、暂停、提交 |
| 错题本 | `#/mistakes` | 掌握度/题型/搜索筛选、详情、历史、选题保存复习套题 |
| 学习记录 | `#/records` | 状态/模式筛选、恢复作答、查看结果 |
| 结果 | `#/result/history-math` | 分数、用时、题目结果与答案解析 |
| 设置、回收站 | `#/settings`、`#/trash` | 标签颜色自动保存、产品信息、资料恢复 |

统一样式在 `styles.css`，通用图标、控件、弹窗在 `ui.js`，页面按内容管理、答题、学习记录拆分。`store.js` 独立负责演示数据与保存；没有页面直接访问数据库或后端。资源由 allowlist 本机服务器提供，无外部CDN依赖。

顶部工作区支持卡片页签：普通导航替换当前页签，仅无背景加号新建首页页签，最后一个页签保留。当前浏览器会话用sessionStorage恢复页签及各自的搜索、筛选、勾选、滚动和返回位置，同一页面可以在两个页签中独立打开。资料库文件夹在主区打开，类型与文件标签使用并排多选下拉；套题属性在标题下方单栏展示。共用下拉菜单及复选框参照HeroUI的控件结构与状态，保留原生表单值和键盘操作；此原型未安装HeroUI React组件。

## 数据边界

错题本提供独立套题、文件夹、题目标签、题型和日期筛选；组合条件与搜索共同作用，更改筛选会清除隐藏勾选。资料库单独使用类型/文件标签下拉，所有多选采用包含式全选：全部与各子项同步勾选，空选不同于无限制。设置中的“标签颜色”分别管理文件和题目标签，选中保持标签原色；改色自动保存，无保存按钮。

文件夹可编辑属性、导出当前子树、移入回收站并恢复；本工作台文件夹JSON归档可重新导入，生成新内容身份，保留原学习记录。它使用 `quarry-preview-folder`，不等同正式 `.quarry` 备份。桌面展开侧栏统一280px。首页布局铅笔仅预留入口，自定义组件尚未实现。

资料库仅显示当前文件夹的直接子项；套题题目区可搜索，并通过加号新建或从题库选题。错题卡片按来源套题文件名与题目标签展示，右侧“斩”标记掌握、“复”撤回，详情随整页滚动。计时显示为MM:SS（超过一小时HH:MM:SS）；首页错题概况已恢复。

题库/套题的“编辑属性”支持名称、简介、文件标签；套题另有时限、跟随开关与更新预览。题目行的“编辑”支持题型、题干、选项、正确/参考答案、解析、分值和题目标签，字段按题型调整。编辑保留选项身份并递增版本，既有作答快照不变；未跟随的套题副本独立编辑。模拟跟随保留套题分值，关闭时冻结当前内容，来源删除时保留最新副本。

打乱开关只在创建套题时出现。工作区顶部固定；管理页返回/前进/首页按标签隔离历史。答题时计时和暂停/结束位于可收起的加宽侧栏，“查看答案”会提交并锁定当前尝试。题号配色为用户已确认的已答灰深绿、当前鲜松绿加外圈、未答浅底。

这是可操作的设计原型，未接真实API。示范数据来自 `data.js`，刷新后从当前浏览器的localStorage恢复，键为 `quarry-unified-preview-v1`；删除该键即可恢复初始数据。保存失败会保留原状态与表单输入。

模拟对象是界面投影，并非 `packages/shared` 的HTTP DTO；后续正式集成需经过API适配层。题目与会话快照、选项身份判分、错题先保存套题再作答等交互遵循产品关系。首页历史统计为既有首页的展示数据，新增本地会话叠加作答量和用时；历史去重基线未模拟完整936题集合。

JSON导入仅支持此工作台自身导出的 `quarry-preview` 格式，不等同正式Markdown/Quarry导入、备份或还原。题干与解析目前为转义纯文本；完整Markdown、数学公式、材料/附件编辑、来源追随、正式打乱规则和后端判分仍属正式集成工作，不以原型替代。

## 关于页面与产品资料

产品名称、英文名、简介和作者/链接统一放在仓库根目录 `product-info.json`；版本只取根目录 `package.json` 的 `version`，不要在页面或产品资料里重复写版本。

- `author.name`：作者展示名；`author.url`：可选作者主页。
- `links.project`：项目主页；`links.contact`：联系链接，可为HTTP(S)页面或 `mailto:` 地址。
- 未填写的作者/入口不显示；作者主页与项目链接只接受HTTP(S)，所有文本经过转义。

预览服务启动时将这份资料和版本注入只读ES模块 `/product-info.js`，由 `pages/about.js` 渲染。这是构建时元信息的预览适配，不是业务API，也不写入用户数据库或localStorage。修改产品资料或版本后，重启预览服务。正式前端构建应在构建阶段生成同一数据对象。
